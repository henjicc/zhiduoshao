# 项目上下文

## 目标与边界

- 产品：「知多少」，一张会生长的知识地图。用户输入问题，先得到有来源、有时效的答案；系统再从答案延伸出具体问题（主动替用户提问），用户点开问题继续得到答案，逐层展开成画布上的知识树。
- 产品形态：Tauri 2 桌面应用（Windows 安装包分发），没有任何后端服务。用户在应用「设置」里填写自己的 API Key，应用在本机直接请求腾讯接口。
  - 不做纯网页版的原因：元宝搜索与 TokenHub 均不允许浏览器跨域调用（2026-10 实测预检分别返回 403 / 405），网页无法直连；用户已明确不要服务器或转发。
  - 唯一例外是开发工具（2026-10-29 加）：开发时（`npm run dev`）浏览器里的请求由 Vite 开发服务器转发，并可采集、重放数据包（见「运行与验证」的演示模式）。它只存在于开发服务器上、只给开发与演示录制用，不对用户发布；发布版和桌面应用（含 `app:dev`）的请求路径不变，不能借它做网页版或给用户提供转发。
- 接入范围：只接入腾讯：大模型为混元（TokenHub 按量 API Key），搜索为元宝搜索（服务 API Key）。这是腾讯项目的约束。
- 已确认的核心交互：
  - 问题 → 答案 → 延伸问题（只有标题，点开才检索）→ 答案，循环往复；任意答案可追问。
  - 模糊起点（2026-10-29 用户确认）：首页可以只写一句念头、情绪或处境（如「手机卡了想换，但今年手机都涨价了，现在买总觉得亏」），占位文字为「想知道什么，或者在纠结什么？」。回答提示词只在探索的第一层（路径为空、不是看看新进展）加 `frameRule`：能直接回答的问题照常回答；是念头时用「拆题：」代替「结论：」，一句话说清对方其实在决定哪几件事，要点 0 到 2 条、只写可查证的事实，不写数据卡片，追问 3 到 5 个方向、第一条带先问。解析器把「拆题：」按结论流式输出并发一次 `framed` 事件，存为 `GNode.framed`（重新回答清空），卡片标签显示「拆开来看」。检索规划要求念头只搜里面可查证的事实，不搜情绪。模型把明确问题误判成念头时用户仍有方向可点，代价小；不联网时同样适用。
  - 无限画布：拖动空白处平移、鼠标滚轮与 Ctrl + 滚轮缩放（每次事件幅度封顶约 12%，由 `createSmoothZoom` 在对数空间按 50ms 时间常数平滑趋近，期间比例被其他操作改动就放弃剩余缩放；触控板双指滑动也是缩放，捏合缩放；触屏单指平移、双指捏合）、按住 Shift 从任何位置拖动框选（从卡片上开始也行）、按住 Ctrl/⌘ 点击逐个加选（不相邻的节点也能一起选，Shift 点击不再加选）；选中的节点按选中顺序用强调色虚线串起来（`.sel-link`）；选中两个以上节点后自动弹出「想对它们做什么？」，预设总结 / 找出关联 / 进一步了解 / 扩散，也可自行输入，结果生成综合节点并以虚线连回来源节点。
  - 回答卡片的问题行（2026-10-29 用户反馈问题和回答一样重、根节点问题占一大块）：问题、方向标签与附图放在卡片上方（`.card-head`，在 `.node` 里、`.card` 外），排法与延伸问题相同（问题靠左、13px 墨色，各节点同一种样式、不随当前或悬停变色（2026-10-29 用户要求一致）；方向标签在右，2026-10-29 用户要求标签放右边。问题行没有框，问题和标签贴着卡片左右两边、各收进 6px（卡片 14px 圆角，文字贴直边看上去会往外探，用户要求视觉对齐）；延伸问题有框，按自己的内边距问题靠左、标签靠右，各按自己的容器对齐，不用固定偏移去和对方对齐），延伸问题点开后文字基本留在原处；卡片里只放回答，第一眼是结论。根节点不再显示「初始提问」，拆题仍标「拆开来看」。问题行离自己的卡片 8px、离上一个节点 16px。问题只显示一行（用户要求），放不下的末尾羽化渐隐（不用省略号）；点一下问题行在原处浮出完整问题（`.card-q-full`，最后一行压在原来那一行上、往上长，不推动布局），再点、点别处或按 Esc 收起，按住拖动仍是拖动节点（`Canvas.tsx` 按拖动阈值区分，状态为 graph store 的 `headOpen`）；一行放得下时点击没有反应。点问题行不再切换当前节点或打开详情，打开详情点卡片本身（第二次点）或卡片右下角的按钮。首页提问框形变时，问题行由单独的飞行层从输入框文字处移上去（`transition.ts` 的 `flyingHead`）。
  - 当前节点（2026-10-29 用户要求一眼认得出，侧栏开着时就是侧栏里的那个）：卡片边线用当前路径连线的颜色（`--edge-active`）加一圈同色细线，再浮起一层（`--shadow-3`）；悬停只是边线深一阶，多选是强调色加光圈，三者分得开。切换当前节点一律经 `core.ts` 的 `focusOf`，侧栏开着时随之切到它的详情，二者始终一致。
  - 拖动与选字：卡片上方的问题行是拖动节点的把手（没拖动就是点开或收起完整问题）；卡片里的结论、要点、智能卡片可以选中复制，没拖动也没选中文字时按点击处理（加载中的卡片整张可拖）。延伸问题整个可拖。折叠按钮放在卡片外、连线起点（卡片第一行高度）上，不压住正文。
  - 右键菜单（[`ContextMenu.tsx`](../src/canvas/ContextMenu.tsx)，只接管画布，侧边栏等处保留系统菜单）：节点上有复制（选中的文字）、打开详情、重新回答（重新检索并重新回答，节点只留这次的结果，已回答的子节点保留，没回答的延伸问题换成新生成的；用户要求，2026-10-29）、断网对比 / 联网对比、导出（存成 Markdown 文件；右键的节点在多选里时另有「导出选中的 N 个节点」）、关闭；空白处有「新建问题」（在点击处、压住节点就往下挪，另起一棵树便于对比，`actions.startHere`）、导出（整张地图）、适应画布。2026-10-29 用户要求精简：复制为 Markdown 与导出合成一项「导出」，菜单用词简短、同一操作各处同名（卡片右下角按钮与菜单都叫「打开详情」，总结面板的导出按钮也叫「导出」）。
  - 关闭（2026-10-29 用户要求，`actions.close`）：后续点开、回答过（或正在回答）的节点，以及自己输入的追问，右键「关闭」变回点开之前那条延伸问题（同样的问题、方向与先问理由，看看新进展保留起始日期），它的回答和下面长出来的整棵子树去掉，进行中的请求取消；根节点（含对比、综合节点）没有这一项。丢掉的是付过费的回答，轻提示带「撤销」：子树原样放回（关闭时还在回答的按中断处理），主线、当前节点、选中、展开状态、详情侧栏与根锚点、子树尺寸都恢复成关闭前的，节点各回原位；那条问题已被重新点开、或已换到别的地图时不再撤销；综合与对比节点指向被关闭的节点时，连线不画，重新回答只用还在且答完的来源节点。节点表的变化由 `core.ts` 的 `closeAnswer` / `reopenAnswer` 算（有单测），存档随节点变化照常写。Markdown 由 [`lib/export.ts`](../src/lib/export.ts) 生成（有单测）：每个节点一节，智能卡片转成表格，详解去掉 [图n]，来源列表带链接；导出经 Rust 命令 `save_markdown` 弹出系统「另存为」（tauri-plugin-dialog 只在 Rust 侧用，界面传不了任意路径），浏览器示例模式直接下载。
  - 拖上去连接：拖动回答节点时悬停在另一个回答完成的节点上，目标描边并浮出「松手，把它们连起来」（用 `--viz-accent`，默认墨色方案的主题色太淡），松手后节点回到原位、两者被选中，弹出「想对它们做什么？」。与 Shift 框选、Ctrl 加选并存。
  - 并排对比：节点右键「断网对比」（原节点没联网时是「联网对比」），生成固定联网方式的对比节点（`GNode.searchMode`，不跟随顶栏开关；`compareOf` 指回原节点，点线连接，卡片标签同样是「断网对比 / 联网对比」），放在原节点右侧空位；对比节点不再提供这一项，也不计入个人记忆的提问。
  - 节点三层信息：卡片（问题、结论、来源图标、时效）→ 激活后展开要点（带来源角标）→ 再次点击打开详情侧边栏。卡片结论是用户第一眼要看的答案：提示词要求第一句就是精准答案（结论、数字、日期、是或否、做法），样式为中等字重、墨色。侧边栏不再重复卡片内容（用户要求）：标题栏只留一行问题，正文从「详解」开始，之后是来源（含「搜索更多来源」「看看新进展」）与延伸问题，不再有结论、要点与单独的「相关图片」区。「详解」默认在侧边栏里点「生成详解」才生成（按钮紧跟「详解」标题、左对齐；设置「打开详情时生成详解」可改为自动，`autoDetail`，用户要求默认手动）（`pipeline.detail`，主模型，Markdown 子集，复用节点来源），存在 `GNode.detail` 并随存档保存，节点重新回答时清空。详解里穿插配图：[`lib/pics.ts`](../src/lib/pics.ts) 先按元宝的图片描述去掉截图、网页、标志、图标、二维码、广告、头像等，并去重、限 8 张、编号，交给写详解的模型；模型在相关段落后单独一行写 `[图n]`（最多 3 张，可以不放），渲染为带说明与来源的插图，加载失败即隐藏。详解与总结的 Markdown 子集由 [`lib/markdown.ts`](../src/lib/markdown.ts) 逐行解析（标题、段落、无序 / 有序列表、`**粗体**`、单独一行的 `[图n]`）：模型常用单个换行分隔标题、正文和列表，不能只按空行分块。卡片上的要点完整显示，不做截断。
  - 智能卡片（`GNode.visual`，[`VisualCard.tsx`](../src/components/VisualCard.tsx)）：只在有搜索结果时，回答格式里多一行可选的「数据：」JSON，六种：柱状 bar（数值比较，可标 highlight 突出一项、其余变灰）、折线 line（随时间变化，悬停看各点）、环形 donut（构成）、表格 table、时间线 timeline、关键数字 stats，由模型按数据用途选，只画能直接回答这个问题的数据（问为什么涨价画成本涨了多少，问要等多久画走势），同一话题下的背景数据（别的地区、人群、品类、后果）不画，没有或拿不准就不写（2026-10-29 实测一句话问三件事，第一层画了和问题无关的「各市场手机零售涨幅」）；[`format.ts`](../src/core/format.ts) 的 `parseVisual` 校验并丢掉没有来源角标的条目，卡片里每一项都带角标（用户要求「可信」，数字不能是编的）。显示在卡片结论下方、和要点一起展开，详情侧边栏不重复。配色（[`tokens.css`](../src/styles/tokens.css)）：单一系列与装饰用 `--viz-accent`，默认墨色方案的强调色是灰，所以用 Radix blue，其他配色方案用各自强调色阶；环形图用固定分类色 `--viz-1..5`（Radix blue、tomato、jade、violet、pink，浅色 10 阶、深色 9 阶），按顺序取用，深浅两套都用 dataviz 校验脚本验证过；底色 `--visual-bg` 是同一色阶的淡层（浅色 3 阶、深色 2 阶）；文字只用墨色令牌。纯 SVG / CSS 绘制，没有图表依赖。卡片里每项最多留 3 个来源角标（解析时截断），显示前 1–2 个、其余折成「+N」，表格每行只显示 1 个；用户反馈角标挤乱排版。提示词要求能用数字图表就不用表格，问「提升多少」用关键数字写各项幅度，柱状、环形和表格里并排比较的各项要是同一时期、同一口径，随时间的变化用折线（2026-10 实测把 GPT-3 与 2026 年模型的参数并排画成柱状图）。回答节点宽度 380px（`--card-w`，原 340，用户要求加宽）；延伸问题与输入框同宽（`--pill-w` 取 `--card-w`，原 260，用户要求）。不做地图与股票走势（没有可用数据源，用户不做财经）；天气等垂直数据只有元宝返回 VR 卡时才有。
  - 回答偏好（[`PrefsMenu.tsx`](../src/components/PrefsMenu.tsx)，设置里的 `prefs`，即改即存）：首页输入框与画布顶栏的「联网搜索」旁边，回答风格（自动为默认 / 简洁明了 / 通俗易懂 / 详细深入 / 自定义一句话；自动不加详略要求，由模型按问题决定，2026-10 用户反馈原默认的简洁明了答得太少、读完还是不懂，设置版本 3 把原来选简洁明了的改成自动；按钮上只显示不是自动的项，全是自动时显示「回答偏好」）、来源（自动 / 权威优先）、时间（自动 / 近一周 / 近一个月）。风格只改措辞与详略，作用于回答、综合与详解；卡片的结论与要点长度只在 `prompts.ts` 的 `LENGTH` 定义（简洁明了、详细深入各一套，其余按问题决定），`styleRule` 与 `READER_RULE` 不写长度或条数，否则几处要求互相矛盾（2026-10 实测选了简洁仍写出六条长要点）；权威优先写进检索规划提示词；时间范围像「看看新进展」一样由程序统一限定所有查询的 `Freshness`。回答提示词另有 `READER_RULE`：按提问方式判断对方懂多少，问得越短越基础（如「PHP 是啥」）越按入门读者答，先用大白话说清是什么、拿来做什么，要点里带一个具体例子（条数按 `LENGTH`，自动时 4 到 6 条）、术语顺手解释；问题带术语、条件或对比时直接给精准答案（用户要求：问得简单说明啥都不懂）。用户选了自定义风格时不加这条。
  - 个人记忆（[`src/memory/`](../src/memory/)，本机 localStorage `zds-memory`，不上传；用户要求「越用越强」）：记忆就是一段文本（≤800 字，每行一条），原样交给检索规划与写答案，用户在设置「记忆」的文本框里直接改（用户要求：不分类、不分条管理）。
    - 信号：来源网站的点开与侧边栏阅读（`recordSite`）、延伸问题各角度的出现与点击（`recordAngle`）、第一次回答的提问与手动生成详解（进 `pending`）。
    - 整理：攒够 4 次提问后由快速模型（`completeFast`，FAST_MODEL）在后台把信号合进记忆文本、输出整段新文本（`consolidate.ts`）：现有内容尤其用户手写的优先保留，不写隐私；近期提问按地图分组、以地图标题为组名，并带上其他最近提问过的地图标题（最多 12 张，`run.ts` 的 `RECENT_MAPS`；只取开着记忆时提问过的地图，记在记忆的 `maps` 里），一个领域至少出现在两张不同的地图里才写成关注领域，同一张地图里顺着追问下去只算一次探索；使用信号只写成事实（如「常点对比类追问」），不改写成对回答的要求，因为写答案时记忆里的回答偏好会照做（2026-10 实测：平铺提问时一次探索就被记成长期关注，「常点区别类追问」被写成「回答时主动做概念对比」）；空输出或整理期间用户改过记忆就不覆盖，信号放回下次再试。
    - 使用（`brief.ts`）：记忆文本交给检索规划（里面写的常看网站对口时可限定，落到元宝的限定站点参数上）与写答案（偏好照做）；另从历史地图里找相似的问题（去掉问句套话后 Dice ≥0.4 且共有 ≥3 个二元组，最多 2 条），把结论交给写答案，懂了的不再从头讲。
    - 透明可控：卡片要点下方一行标出记忆里写到、检索时真的限定过的站点，以及「你探索过」的历史问题（可点开那张地图）；设置「记忆」总开关；回答偏好弹层里可设「这张地图不用」（不记录也不使用，`offMaps`）。
  - 引用角标点击弹出引用气泡（[`CitePopover.tsx`](../src/components/CitePopover.tsx)）：来源标题、站点、原文，与被引用那句话最相关的一两句高亮（荧光笔黄 `--mark`，阅读视图当前句 `--mark-strong`，取 Radix yellow a4/a5，深色 a7/a8，不随配色方案变；原来用强调色淡底，墨色方案下几乎看不出，用户反馈）（[`lib/match.ts`](../src/lib/match.ts) 按字二元组重叠打分，纯本地、不调用模型；读过全文的先在全文里找，找不到回到摘要；低于门槛就不高亮并说明，不硬凑），底部「打开原网页」用系统默认浏览器，节点里的角标另有「在侧边栏阅读」（按设置决定哪个是主按钮）。画布平移缩放、抽屉切换、滚动时关闭，别的节点流式输出不打断它。实测（2026-10，DeepSeek 话题 12 个角标）10 个找到对应句子，没找到的是模型的抽象概括。
  - 打开来源：设置「点击来源时」可选系统浏览器（默认）或侧边栏阅读视图（`openSource`）；来源列表、气泡都按它走，没有链接的权威卡片只能在阅读视图看。外链统一用 [`lib/external.ts`](../src/lib/external.ts)（模拟点击 `target="_blank"` 链接，由 opener 插件交给系统浏览器；它不检查 isTrusted，阻止默认行为后不会再打开）。
  - 来源阅读视图（[`Reader.tsx`](../src/components/Reader.tsx)，graph store 的 `reading`）：侧边栏里逐层进入，顶部「← 详情」、路径「节点 › 来源 n/总数」、上一条 / 下一条、浏览器打开；没读过全文的打开时自动读取（先显示摘要），读到后写回 `Source.text`（写答案、气泡也能用；回答还在检索时，研究 Agent 发来的来源列表按 id 保留这里读到的全文，见 `runs.ts` 的 `sources` 事件）；这个节点里所有引用了该来源的句子（`match.quotesFor`：结论、要点、详解）列成可跳转的条目并在正文里高亮。← → 切换来源，Esc 先回详情再关侧边栏。切换节点或重新打开详情时退出阅读视图。
  - 侧边栏宽度：拖左边缘调整、双击恢复 420，记在设置 `drawerWidth`（360 到窗口 60%），写到 Workspace 的 `--drawer-w`，画布的可用区域（`view.viewport`）同步；窄窗口时占满。切换节点时上一个节点的要点默认保持展开（用户要求，设置版本 2 迁移时老用户也改一次），设置里可改为自动收起（激活过的节点记在 graph store 的 `opened`，随存档保存为 `MapRecord.opened`，重新打开地图后保持展开）。
  - 延伸问题的角度标签（卡片上的 `dir`）由模型按问题自拟 2 到 4 字，数量由模型决定（最多 6 条，宁少勿滥），不再是固定列表；用户追问的节点 `dir` 为「追问」。问透：结合探索路径看，起点的疑问已经解开、再往下只剩细枝末节时写「追问：无」；起点拆成几件事时，每件都要在路径上有一层专门答过（别的回答里顺带提到的不算），推荐先问指向还没专门答过的下一件，可以和地图上已有的问题相近但要更具体；回答提示词里「已有问题」标明不代表回答过（实测 DeepSeek 把列在地图上、还没点开的问题当成答过，第二层就写无）。实测（2026-10-29）：手机念头拆成三件事，顺着先问在拆题后第 4 步问透，前几版提示词要么 5 层都不收、要么第 2 层就收；普通问题在第一层没有被误判成念头，也没有写无。解析器据此不产出延伸问题并发 `settled`，存为 `GNode.settled`（重新回答清空）；没有子节点、也没折叠时，`layout.ts` 在子列最前面留出收尾位（`ends`，输入框照常接在下面），连线照常画出、末端是实心小点，旁边写「这条线问透了」（13px、ink-3，`Canvas.tsx` 的 `EndMarks`）；之后再追问长出子节点，记号自动消失。天气这类单一事实问题在第一层就问透是正常的。推荐下一步：第一条追问写成 `[角度] 问句｜先问：理由`（理由不超过 14 字），解析器只认第一条（后面的去掉标记），存为问题节点的 `GNode.nextWhy`；模型漏标就不标，程序不硬选；输入框补出来的方向不带。界面上不特殊显示（2026-10-29 用户要求）：画布药丸、侧栏「延伸问题」、总结面板「还可以再看的」都和其他条一样，`nextWhy` 只用于排序（路径回看里排在前面）、提示词和总结导出的 Markdown；药丸保留 `is-next` 类名，只给自动化脚本找这一条。
  - 延伸问题出现的时机（2026-10-29 用户要求）：看着答出来的节点，延伸问题、底部输入框与问透记号等这个节点的内容全部放完（结论、图表、要点都放出，即卡片 `data-done` 的时刻）才出现，先按最终位置排好但不显示（`.is-held`，连线也不画），放完后用节点的出现动效淡入、连线随之长出；回答还在输出时冒出来会抢注意力。状态是 graph store 的 `revealing`（`AnswerCard` 维护，不存档）；打开历史地图时卡片不重播，延伸问题照常直接显示。
  - 每个回答完成、没折叠的节点，延伸列表最下方都留好一个输入框的位置（`layout` 的 `slots`，不是节点，2026-10-29 用户要求）：当前节点的常显（带 `is-current`，自动化脚本往它里面打字）；其余平时透明，鼠标移到这个节点或输入框的位置上时淡出显示、移开稍等一拍淡出，有焦点、打了字或正在理解时保持显示，连到它的虚线同样淡入淡出（`NodeView` 的 `slotShown`，graph store 的 `hovered`、`slotKeep`）；位置一直留着，出现和消失不推动布局。各输入框各自判断意图、互不阻塞（`slotBusy` 按节点记）。输入的内容交给 [`router.ts`](../src/core/router.ts)（跑在 Agent 内核上、只走一步），轻量模型判断意图——ask 则把输入改写成完整问句、新建追问节点并回答；branch 则在该节点下补充新的探索方向（数量自定、最多 6 条）；拿不准或解析失败按 ask 处理。
  - 兄弟节点按实际占地紧凑排列（`layout.ts`：后一个兄弟只避开左右重叠的后代，不把整棵子树当矩形，否则右侧子列很长时下方会空出一块；后一个兄弟的卡片本身只避开同列的节点、贴着上一个兄弟放，它的子列撞上右边别人的子列时单独往下挪（主线前的兄弟镜像往上挪），不连同卡片一起推远，2026-10 用户反馈卡片被推到很远的下方）；当前路径高亮、其他分支变淡（回答卡片 0.55、延伸问题 0.8、连线 0.5：用户要求别的方向一直看得清，引导换方向继续问）；卡片的时效写作「最新信息发布于 …」；来源时间（`lib/format.ts` 的 `relativeTime`，卡片、来源列表、引用气泡、阅读视图共用）：元宝的 date 形如「2026/10/23 21:39:54」，多数带具体时刻，带时刻的显示到分钟（今天 21:39、昨天 08:15、10月19日 21:39，跨年带年份；用户要求突出分钟级更新），只有日期（00:00:00）的按天显示相对时间，按日历日计算，指最新来源的发布时间而不是提问时间；面包屑回退；分支折叠；缩小画布时节点原样显示、不做简化（用户决定，2026-10：只显示标题会让卡片变矮、布局重排，内容重新显示时浮现动画重播；改成尺寸不变、只留标题又显得空，最终去掉）；平移缩放时画布（`.world`）临时加 `will-change: transform`（`is-moving`，停止 180ms 后撤掉）：过程中按图层拉伸保证帧率，停下后按最终比例重绘保证清晰；节点不能常驻 will-change，否则放大后一直发虚（用户实测）；总结面板支持整张图 / 当前路径 / 选中节点，可复制或下载为 Markdown（正文加实际引用的来源，文件名取总结标题）；打开时有选中节点就总结选中的，否则当前路径走到两层以上（路径上已答的节点 ≥ 2）默认「当前路径」，再否则整张图（2026-10-29 起，原来默认整张图）；「当前路径」正文顶部是路径回看（[`PathReview.tsx`](../src/components/PathReview.tsx)），原来的总结文档在下面：起点与现在左右对照（20px、600，中间一条 SVG 细线，每走一步一个点、悬停看那一步的问题，终点实心点与画布的收尾记号相同，窄窗口上下排列；路径只有一层时不显示），已经弄清的 3–5 条（快模型 JSON 模式 `pipeline.review`，每条一句、带角标，角标沿用 `mergeSources` 的序号、与总结正文一致；结果只缓存在内存里、不存档；失败时只隐藏这一块；实测约 6–7 秒），还可以再看的（路径上还没点开的问题，先问排前面，最多 4 条，复用 `.followup`，点一下关掉面板开始回答；没有时不显示）；动效依次是起点淡入、线画过去点依次出现、现在淡入、逐条放出已经弄清的，只用 `--t-mid` 与 `--t-reveal`，减少动态效果时不延迟；复制与下载的 Markdown 在标题之后带上这三块；面板一打开就是固定的大尺寸（最高 820px），不随内容撑开；没开始输出时上面是思考流、下面是带光泽的占位横条，开始输出正文后整块换成内容；来源列表一行一条（标题与站点日期同行，不显示摘要）。
  - 窗口外观：无系统边框，自绘标题栏（[`TitleBar.tsx`](../src/components/TitleBar.tsx)）。画布顶栏即标题栏，首页有一条透明标题栏；空白处拖动、双击最大化，右侧为 Windows 风格窗口按钮，失焦变淡；发布版屏蔽 WebView 右键菜单（输入框除外）。新增顶栏元素时，容器保留 `drag` 属性，可点击的子元素不要加。
  - 并行与离开：可以同时点开多个延伸问题，各自独立回答；进行中的节点不参与非当前路径的变淡。离开还在回答的地图（点标题栏左上角的返回图标回首页、从历史打开别的地图，统一走 `actions.leave`）时按设置 `onLeave` 处理：后台继续（默认，不打断用户，回答完会提示）、每次询问（弹出 [`LeaveDialog`](../src/components/LeaveDialog.tsx)：只有标题，没有说明文字，右上角关闭即留在当前地图；左下「记住我的选择」默认不勾；右下危险色字的「全部终止」与墨色实底的「后台继续回答」）、终止；设置「画布与来源」里可改。在后台继续：地图状态移到 `core.parked`，进行中的回答 / 综合 / 详解经 `patchAt` / `addAt` 写回那里（新节点接着该地图自己的最大编号），延迟存档；全部完成后立即存档、移出后台并提示「已在后台回答完成」带「打开」；放到后台时立刻加进历史列表（第一个回答还没完成、尚未存档也加，打开时用内存里的状态；全部失败则移除），首页与历史列表显示转圈的「后台回答中」且不能删除；确认弹窗开着时已经答完的，选后台继续也不进后台、照常自动保存（否则没有结束事件把它移出后台）；再次打开时直接用内存里的最新状态，进行中的请求继续写回画布。输入框的意图判断在离开时一律取消。关窗时后台地图也写一次，未完成的节点下次打开标为中断。
  - 对话框（设置、历史、总结、离开确认）只盖住内容区，标题栏保持清晰可用；设置在宽窗口（≥ 900px）分两栏：左边两个密钥，右边画布与来源；面板高度不超过可视区域，内容在面板内滚动。
  - 设置入口：首页右上角与画布顶栏的齿轮按钮；密钥未填全时提问会先打开设置；密钥类错误的卡片提供「设置」按钮。
- 设计风格：专业、简洁、克制、高级。用户否定了朱砂（偏橙）强调色：默认配色为「墨色」（中性冷灰，强调色是石板灰，几乎只有黑白灰）；设置「外观」可换靛青、石青、松绿、胭脂、黛紫（`settings.palette` → html 的 `data-palette`，令牌在 [`tokens.css`](../src/styles/tokens.css) 末尾，每套各有浅色与深色，在首次渲染前写到 html 上）。明暗在「外观」里选跟随系统 / 浅色 / 深色（`settings.theme` → html 的 `data-theme`，跟随系统时不写）；新用户默认深色（2026-10-29 用户要求，原来默认跟随系统），已经存过设置的保持原样、不迁移（存档里没有明暗的按跟随系统）；`tokens.css` 里每个深色块写两遍（系统深色且未选浅色、选了深色），改深色令牌时两份要一起改。窗口无系统标题栏（`decorations: false`），不需要同步原生窗口主题。颜色全部来自 Radix Colors（用户要求）：每套配色是一条灰阶加一条强调色阶（墨色 slate+slate、靛青 slate+indigo、石青 sage+teal、松绿 sage+jade、胭脂 mauve+crimson、黛紫 mauve+violet），色阶由 `@radix-ui/colors` 3.0.0 的官方值生成，语义令牌按 Radix 分阶用法映射一次；浅色下画布（`--bg`）用灰阶 3、卡片与面板用 1，卡片像纸放在浅灰桌面上（2026-10 用户觉得满屏发白、卡片和背景分不开，从 2 压到 3，比较过暖灰 sand 方案后选了这一版）；直接压在画布上的控件（顶栏、首页标题栏、首页「最近」）悬停与按下用 `--bg-hover` / `--bg-active`（4 / 5 阶），否则与底色同色；危险色（终止、错误）用 red。字体全站统一无衬线（用户否定了衬线与无衬线混用）：`--font-ui` 依次为 -apple-system（苹果即苹方）、HarmonyOS Sans SC、MiSans、苹方、微软雅黑，苹方须排在 HarmonyOS 之后（有的 Windows 也装了苹方）；不加载网络字体。Logo 例外：首页与画布标题栏的「知多少」用 [`Wordmark`](../src/components/Wordmark.tsx)，是思源宋体 Heavy（OFL）的字形轮廓 SVG（字间距 0.14em，颜色跟随 currentColor），用户电脑不需要装这款字体；用户从多款宋体与设计稿中选定。首页字标左边是应用图标里的红梅（[`Plum.tsx`](../src/components/Plum.tsx) 的 `PlumMark`，去掉底板与落瓣，颜色用图标品牌色、不随配色方案变），花右下缺口每隔 2.5–5.5 秒飘出一片花瓣，同屏最多 4 片（用户确认的方案 A）：落瓣层挂在 body 上、压在输入框之上，全局风向来回变、每片另加湍流，一直落到窗口外；离开首页（含提问框形变成卡片）后不再生成，已有的升到形变外壳之上边飘边淡出，与形变无缝衔接；减少动态效果时不飘；设置「外观」的「首页花瓣飘落」可关闭（`settings.petals`，默认开启，关闭后花仍在、不再生成花瓣，已在飘的淡出）。字号只有 12 / 13 / 15 / 20 四档（用户要求不超过四种、最小 12px），层级靠字重与颜色：标题 600、结论 500、正文 400；阅读正文（详情、总结、阅读视图）用 15px、`--read-lh` 1.85、`--read-track` 0.01em。线条 0.5px，动效基础 250ms ease-out，见 [`frontend-ui.md`](frontend-ui.md) 的视觉基线。用户已否定「星图风」「纸面笔记风」等装饰性方向。

## 权威入口与特殊约束

- 编排与契约都在前端 [`src/core/`](../src/core/)：
  - [`protocol.ts`](../src/core/protocol.ts) 定义界面与编排层之间的请求和流式事件；界面只通过 [`src/api/client.ts`](../src/api/client.ts) 调用编排，并在这里把异常统一转成带 `code` 的 error 事件。
  - Agent 内核 [`agent.ts`](../src/core/agent.ts)：模型每一步（快模型、JSON 模式）输出一个 `{"action": ...}`，程序按注册的动作逐个校验参数并执行，结果作为观察喂回同一段对话，直到动作给出结果或预算（步数、时长）用完；输出不合法时走调用方给的兜底动作，每一步写调试日志。新增 Agent 能力就是注册动作，不另写循环。
  - 研究 Agent [`research.ts`](../src/core/research.ts)：动作 `search`（查询词 1 到 4 个，各自可带时间范围与领域；首轮来源总数 5 到 20 由模型定、每个查询词至少 4 条，补搜每轮最多 2 个词、新增 6 条）、`read`（摘要不够深时读来源网页全文：每次最多 3 篇、整个研究最多 4 篇，正文挂到 `Source.text`，写答案时优先用全文；失败的告诉模型；正文不比搜索摘要长时不算全文、继续用摘要，见 `protocol.ts` 的 `fullTextIssue`，阅读视图同样：2026-10 实测什么值得买页面只提取到 80 多字，却替换掉了上千字的摘要）与 `done`（可带 `drop` 剔除离题、内容农场、营销软文或重复的新来源，每条写 `{"id":序号,"why":理由}`，理由只认离题、内容农场、软文、重复，也接受只写序号（不显示理由）；已有来源不能丢，要全部丢掉时一条不丢）。剔除的来源以 `dropped` 事件存进 `GNode.dropped`（只存来源 id、标题、站点、链接、图标与理由，不存摘要与全文；搜索更多来源时累加、补搜跳过这些 id，重新回答清空），检索过程在「选出 M 条来源」之前加一步「判断：够了，剔除 N 条」，默认收起，点开每行是网站图标、标题与右侧的理由标签，有链接的点一下用系统浏览器打开（没有链接的权威卡片只列出）；没有剔除时不显示。整个循环是同一段对话（`researchPrompt` + 每轮 `researchObservation`），复查看得到之前的规划、各轮结果与上一轮说的缺口；搜索最多 3 轮、决策最多 6 步、约 45 秒；常识、方法类问题判为够；还没搜过就 done 或输出不可用时按原问题搜一轮。提示词示例里不要写具体数字，实测模型会照抄示例值。搜索：每个查询的 `Cnt` 按总数平分取档，多查询交错去重；去重按网址加摘要开头（`protocol.ts` 的 `articleKeys`：去掉空白与标点后前 120 字，不足 60 字只按网址；只比 60 字时会把引用同一段原文的不同文章误认成一篇），同一篇的 http 与 https、转载、arXiv 的 abs 与 html 只留一条，免得写答案的模型把转载当成多方印证；综合合并来源（`mergeSources`）与「看看新进展」跳过上一层来源也用它。复查会剔除来源，回答过程中来源序号可能变化，所以阅读视图按来源 id 定位（`reading.sourceId`）。
  - [`pipeline.ts`](../src/core/pipeline.ts)：看图 → 研究 Agent → 主模型按行格式流式输出 → [`format.ts`](../src/core/format.ts) 增量解析为结论 / 要点 / 追问；另有综合、总结、详解。改提示词（[`prompts.ts`](../src/core/prompts.ts)）的输出格式时必须同步解析器与其测试。

- 提示词（[`prompts.ts`](../src/core/prompts.ts)）：
  - 卡片长度（`LENGTH`）给字数参考（2026-10-29 用户要求修好 DeepSeek Flash 卡片偏长，取代此前「不写死字数」的做法）：只限句数和条数时，DeepSeek 一句话比混元长四到六成，爱用冒号、分号把几层意思塞进一句、把来源里的名字全列一遍，`READER_RULE` 与 `timeRule` 里还有变相规定内容量的清单。现在结论第一句是答案；自动：单一事实一两句、50 字以内，需要理解的问题两到四句、整段 80 到 150 字（大白话说清是什么、必要时打比方、最后一句带出现状），要点 2 到 6 条、每条一到两句 25 到 60 字（单一事实 2 到 3 条）；简洁明了：结论一到两句、60 字以内，要点每条一句、30 字以内；详细深入不变。自动与简洁明了的结论另加句式要求 `SHORT`（每句只讲一层意思，不用冒号、分号或长串并列，列举只挑两三个）；综合与扩散经同一个 `format` 用同样的要求；`READER_RULE` 只要求先说清是什么、拿来做什么、要点带一个例子，`timeRule` 只要求说到现状时以最新情况为准。拆题的长度（不超过 40 字、要点 0 到 2 条）不变。答到点上（2026-10-29 用户实测「手机今年为什么都涨价了？现在换还是再等等？要等多久？」，结论把三件事挤成一团、要点混进「全球出货降 20%」）：一句话问了几件事时，结论按提问顺序每件答一句、都要答到，句数按问题数放宽；每条要点先对照用户问的事，回答或支撑不了哪一问的不写（后果、行业影响、别处或别的人群的情况都算对不上）。用该次真实请求的同一批来源对照，新规则三遍都逐个答到、图表和要点贴题；主案例「现在买还是等」「存储为什么涨」两层没有被误伤。实测（2026-10-29，同一批来源，自动与简洁各 5 题）：卡片平均从约 870 / 380 字降到约 470 / 180 字，内容仍读得懂，拆题与先问照常。结论里不放排名、参数、价格、百分比，不用「到某年某月」开头（2026-10 实测加了时效规则后，模型会把这类数字和日期堆进结论，读起来拗口）。卡片内容区最高 `--card-max-h`（600px），超出在卡片里滚动（问题行在卡片外，不跟着滚）：已往下滚时卡片顶部羽化 24px；下面还有内容时卡片底部羽化（渐隐约 110px，用户嫌 48px 不明显），滚到底消失（`ScrollThumb` 给滚动区域切换 `has-more` / `is-scrolled`）；鼠标在可滚动的卡片上时滚轮只滚卡片，滚到顶或底也不缩放画布（用户要求），Ctrl + 滚轮始终缩放；原生滚动条隐藏（滑块做不了淡入淡出），由 `NodeView` 的 `ScrollThumb` 自绘 3px 细条（悬停变 5px），贴在卡片右内边距、正文宽度不变，悬停卡片或滚动时淡入、停下 0.8 秒淡出，可拖动且不会拖动节点；布局按不超过最大高度的高度排。要点文字用墨色 `--ink`（用户反馈次级灰太淡）。
  - 时效（`timeRule`，回答、综合、详解都带）：只给日期不够，2026-10 实测问「什么是大语言模型」，模型拿 2023 年的数据当现状、最新来源停在 2025 年。规则要求同一件事以最新来源为准、只有旧资料时写「截至某年」，变化快的领域（AI、科技、互联网、政策、行情）说到现状时以最新情况为准（不规定要讲多少现状，写成「讲清发展到哪一步、主要变化」会把卡片撑长），有追问时至少一条指向当前前沿（原来写「追问里至少有一条」，模型几乎写不出「追问：无」）；研究 Agent 对这类领域即使是概念题也至少用一个带 time（y1 / m6）的查询词查最新进展。不在提示词里写死具体话题（如 Agent），由模型按日期与来源判断前沿。
  - 回答以搜索结果为主并标 [序号]；搜索没覆盖的常识、方法、原理允许模型用自身知识补充（不标序号），具体数据、日期、最新动态只用来源；官方、原始出处和主流媒体优先，只有一个不知名网站给出的数字不进结论和数据卡片（2026-10 实测内容农场的数字被做成了数据卡片）；不写「材料未提及」之类的话。不联网时不能断言没听说过的东西不存在（实测把已发布的 iPhone Duo 说成「没有这款产品」）。
  - 规则放 system、材料放 user、问题放最后；给一个格式示例，并要求思考简短、不复述格式；来源摘要整条给模型（元宝动态摘要平均约 1650 字，研究 Agent 读过全文的用正文），后面接「配图：」一行（`captionLine`：元宝的图片描述去重、每条截 40 字、每个来源最多 4 条），模型可引用该来源序号，追问也可从配图线索找方向。
  - 「已有问题」只取路径上的节点、它们的子问题和来源节点，最多 20 条（`relatedQuestions`）。
  - Coding Plan（`sk-sp-`）与 Token Plan（`sk-tp-`）套餐密钥的条款禁止用于自定义应用后端，设置页与注册表都会拒绝；只接受 TokenHub 按量 API Key。资料：<https://cloud.tencent.com/document/product/1823/130092>。
  - 元宝搜索：[`yuanbao.ts`](../src/core/providers/yuanbao.ts)，`POST https://api.wsa.cloud.tencent.com/SearchPro` + `Authorization: Bearer <API Key>`，参数同 SearchPro：已用 `Query`、`Cnt`、`Freshness`、`Industry`（gov / news / acad / finance）、`Site`（限定一个域名，各版本都支持，只对自然结果生效）、`Mode: 2`（自然结果 + 权威 VR 卡）、`Deeplinks`（仅确认是旗舰版后才发）。响应的 `Version`（lite / standard / flagship）按密钥记在内存里，极速版不发 `Cnt`、`Mode`、`Industry`；设置页测试连接会显示版本。

    - 检索规模：研究 Agent 每轮搜索后发 `searched` 事件（去重前返回条数），累计到 `GNode.searchResults`（随存档保存，重新回答清空、搜索更多来源累加）；复查阶段状态显示「元宝搜索返回 N 条结果」，详情抽屉「来源」标题旁显示「从 N 条结果中选出 M 条」（综合节点不显示，其来源含合并来的）。用户后来改了决定（2026-10）：显示元宝搜索的速度与条数。加载时状态写「元宝搜索 0.5 秒返回 N 条」（统一按秒、一位小数；只搜一轮就作答的简单问题在查阅来源时也显示），侧边栏在详解之后有「检索过程」（[`SearchLog.tsx`](../src/components/SearchLog.tsx)，2026-10 用户选定步骤时间线）：竖线串起每一步——拆成几个查询词（附首轮的限定）、第 N 轮同时查 / 补查几个（每条查询一行，参数小标签跟在查询词后、右侧条数）、补查前的「判断：还不够」与研究助手写的理由、读全文几篇（标题，没读成的篇数）、「选出 M 条来源」与去重后条数，最后「写成答案」：读了约多少字（交给写答案的材料，读过全文的按全文）、写成多少字（结论加要点，不算角标），下面一根细条，整条是读的量、`--viz-accent` 的一小段是写的量（至少 2px），让「读得多、写得少」看得见；只用已有字段，早期存档也能显示，综合节点不显示（`lib/format.ts` 的 `readWritten`）；数据存在 `GNode.steps`（`searched` 事件带 `unique`、`reason`，新增 `read` 事件），早期存档没有 steps 时按 searches 只画查询部分。标题旁写「调用元宝搜索 N 次 · 返回 N 条 · 用时」（用户要求不说「N 次查询」），总条数与耗时；数据来自 `searched` 事件里的 `plans` 与 `ms`，存在 `GNode.searches` / `searchMs`。加载时卡片只报阶段与累计数字，不逐轮播报查询词和「第几轮」，每条状态至少停留 1.6 秒、新旧两句叠化切换（`StatusText`），换阶段时思考流接着滚、不清空；用户反馈逐轮切换太快、一闪一闪。检索过程里只在补充的那一轮前加「第 N 轮补充检索」，不回头给第一轮补标题。

## 运行与验证

- 脚本以 [`package.json`](../package.json) 为准：
  - `npm run dev`：只启动 Vite（:17531），供浏览器里用示例模式调界面（`.env` 里 `VITE_PROVIDERS=mock` 时）；不是示例模式时浏览器经开发服务器发真实请求，密钥在页面的设置里填（17531 来源下的 localStorage，与桌面应用不互通）；
  - `npm run app:dev`：桌面应用开发模式，会自行启动 Vite，因此不能与 `npm run dev` 同时运行。用真实接口测试时，先在 PowerShell 里执行 `$env:VITE_PROVIDERS = 'real'` 再运行；
  - `npm run app:build`：生成 Windows NSIS 安装包，位于 `src-tauri/target/release/bundle/nsis/`；
  - `npm run typecheck`、`npm test`（`src/**/*.test.ts`，`node:test`）、`npm run build`。
- 依赖：Node、Rust（stable）与 MSVC 构建工具、WebView2（Windows 10/11 自带）。首次 Rust 编译需数分钟；修改 `src-tauri/` 后 `app:dev` 会自动重新编译。
- 配置：`.env` 只有可选的 `VITE_PROVIDERS=mock`（见 `.env.example`）；进程环境变量优先于 `.env`，桌面开发时可用 `VITE_PROVIDERS=real npm run app:dev` 走真实接口。
- 最低验证：`npm run typecheck` 与 `npm test`。界面改动在浏览器示例模式走通「首页提问 → 加载 → 答案 → 延伸问题 → 多选指令 → 综合节点 → 详情抽屉 → 总结面板 → 设置 → 回首页看最近 → 历史面板搜索、打开、删除与撤销」。
- WebView 的 localStorage 与 IndexedDB 按来源（含端口）隔离：开发版换端口后设置里的 Key 和历史记录都看不到，所以开发版固定用 17531（`devUrl`，选不常见端口是为了避开其他项目；2026-10 从 5173 改过来，Key 需重新填，之前的历史记录留在 5173 来源下看不到）；17531 被占用时要先让出端口，而不是改端口启动。
- 桌面应用 `app:dev` 运行时会占用 17531 端口和 WebView2 数据目录：浏览器示例模式改用 `.claude/launch.json` 的 `dev-mock`（17532 端口）；也不能再启动第二个带调试端口的应用实例（WebView2 报 0x8007139F）。高分屏细节截图可用无头 Edge（`--headless=new --force-device-scale-factor=1.5 --disable-sync --disable-extensions`，独立的 `--user-data-dir`）加 CDP。
- 调试日志（仅开发版桌面应用）：[`src/core/debug.ts`](../src/core/debug.ts) 经 Rust `debug_log` 命令，把每次运行写入 `.debug/network.jsonl`（每行一条 JSON，启动时上一份改名为 `network.prev.jsonl`）。内容包括：
  - `run.start`：请求参数；
  - `http.request` / `http.response`：完整请求体与提示词、状态、首包与总耗时、原始响应，流式响应另拼出 `content` / `reasoning`；
  - `run.done` / `run.error`：解析后的结论、要点、追问与原始错误。
  密钥只留首 6 位与末 4 位，发布版不编译该命令。排查真实请求问题时先读这份日志。
- 存储隔离：Claude 桌面应用是 MSIX 打包的，从 Claude 工具（Bash / PowerShell）启动的进程，写入 `AppData\Local` 会被重定向到 `Packages\Claude_…\LocalCache`；用户终端标签页启动的应用使用真实路径。两边的设置与 Key 互不可见。需要用户已保存的 Key 做验证时，要在用户的终端标签页里启动应用（可临时加调试端口），不要从工具里启动。
- 网络或原生改动必须在桌面窗口里验证：设环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223` 启动应用，通过 CDP 在窗口内执行请求。
- 开发服务：`.claude/launch.json` 的 `dev` 配置运行 `npm run dev`，`dev-mock` 在 17532 端口运行示例模式（就绪信号为 Vite `ready`）；停止时只结束该命令或核对过 PID 的进程。
- 演示模式（数据包，2026-10-29 加，只在开发时的浏览器里有）：真实请求只跑一次，把每次外部调用（模型流式输出、元宝搜索、读网页）的原始返回存成数据包，之后按数据包重放，界面走的是和真用时完全一样的检索、解析与流式逻辑，屏幕上的内容都来自真实请求、不手改。
  - 开关是地址参数（[`pack.ts`](../src/core/pack.ts) 的 `parsePackMode`）：`/?capture=名字` 采集，`/?replay=名字` 重放，可加 `speed`（倍速）、`cps` / `thinkCps`（每秒几字 / 思考每秒几字）、`firstMs`（首包延迟），都只作用于写答案、详解这类正文流；默认照采集时的真实节奏。研究决策、搜索与读网页一律照录制时间：决策有 12 秒时限、研究有 45 秒预算，变快变慢都可能走上和采集时不同的路、请求对不上。采集时超时或被取消的调用，重放时同样等调用方自己取消；采集中途停下、没录完的调用重放时按问题报出。
  - 数据包由开发服务器读写（`/__zds/pack/名字`），存在 `.packs/<名字>.json`（`vite.config.ts` 的 `PACK_DIR`）。不存密钥：请求头与请求体里的密钥字段按名字去掉，请求里见过的密钥值在整份数据包里替换成 `***`。
  - 对应关系：方法 + 网址 + 请求体，日期（YYYY-MM-DD）换成占位后比较，换一天也能命中。采集时同样的请求再发一次（重新处理、刷新后重问）只留最新这次，数据包不会越记越大，重放拿到的是最新结果；同名数据包已存在时接着记。重放时同样的请求按顺序取，都用过了就再用最后一条。对不上时不联网、不改用示例数据：请求失败，控制台写出最接近的一条从第几个字差起，页面底部出现红色错误条。数据包读取推迟到第一次请求。
  - 重放时界面不出现任何「演示」「示例」字样；标题栏照样画出窗口按钮（点了没有作用），画面与桌面应用一致。卡片上「今天 21:39」这类相对时间按重放当天计算。
  - 驱动页面的自动化脚本不在本仓库，按上面的地址参数打开页面。它等「节点答完」看卡片的 `data-done`（[`NodeView.tsx`](../src/canvas/NodeView.tsx)：回答完成且结论、要点都已放出），找推荐先问的延伸问题看 `is-next`，往当前节点的输入框（`is-current`）里打字，采集结束前调用 `window.__zdsPack.flush()` 等数据包写完；改卡片时保留这些标记。
  - 实测（2026-10-29，两层回答加打开侧栏检索过程）：采集 17 次外部调用（研究决策 5、元宝搜索 10、写答案 2），数据包约 2MB、不含密钥；同一份脚本重放两遍，17 次全部命中、没有外部接口请求，两遍截图逐像素一致，与采集时的最终画面只差 1 个像素。页面另会加载来源网站图标（`<img>`，与真用时一样，不经数据包）。
- 费用与权限：真实模式每次提问会调用付费的元宝搜索与 TokenHub 模型。验证优先用示例模式或无效密钥；真实调用只用用户提供的密钥，并控制次数。
