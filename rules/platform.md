# 产品形态与平台行为

> 读取时机：确定产品形态，改变导航、生命周期、系统能力或多端边界时；单纯文案和局部样式不触发。

以用户如何启动和完成任务为准确定产品形态。HTML / CSS、React 或 WebView 是实现技术，不能据此把桌面软件设计成网站。沿用上下文中已确认的平台，只检查当前变化影响的行为，不逐项实现所有平台能力。

| 形态 | 关注的真实行为 |
|---|---|
| Web | URL、历史与刷新、深链接、多标签、会话和网络状态；内容网站按需要考虑 SEO，高交互应用关注状态恢复 |
| 桌面 | 窗口、焦点、关闭与退出、快捷键、文件操作、离线与系统权限；安装更新及多窗口按产品范围处理 |
| 移动端 | 触控、系统返回、安全区域、软键盘、前后台与进程回收；弱网、耗电与权限时机 |
| 服务端 | 契约、鉴权、事务、幂等、并发、可观测性与回滚 |
| CLI | 参数、标准输入输出、退出码、信号与非交互调用，避免提示阻塞自动化 |
| 库 / 插件 | 最小公共契约、宿主生命周期、兼容范围、权限与性能预算 |

- 桌面效率工具优先稳定工作区、键盘效率和合适密度，不因网页渲染套用落地页或巨型卡片。
- 多端共享必要的领域能力和契约，不强求相同导航或界面结构；不存在的边界不为对称而新增。
- 特权能力按实际可信边界安置，具体约束由架构和安全规则负责。
- 平台行为或支持版本不确定时按研究规则核验；已确认的长期限制记录到项目上下文。
